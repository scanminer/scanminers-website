# Mineral Texture Pack

A shared reference for Scanminers' geology-flavoured design system. Use this guide when generating or curating cinematic mineral textures for cards, hero regions, OG images, or any other branded surface.

---

## Technical Specs

- **Format:** WebP (preferred) or high-quality JPG → run through the existing image optimization pipeline when exporting.
- **Resolution:** 1920×1080 landscape. This covers hero modules, editorial cards, and OG/autogenerated assets without upscaling.
- **Composition:**
  - Soft macro/abstract treatment of the mineral; no logos, icons, or text.
  - Dark, moody palette with deep charcoals (avoid full black #000).
  - Subtle vignette with a gently illuminated center to preserve legibility.
  - Keep the texture slightly defocused or with shallow depth of field to avoid noisy overlays.
  - No recognizable people, tools, or machinery.
- **Color grading:** Match each mineral’s spectral identity while staying in the shared dark editorial palette (e.g., desaturated warm gold, cold metallic blues, magenta REE glints).
- **Prompt endings:** Always close generation prompts with `dark cinematic lighting, high-end editorial texture, minimalist, no text`.

### Master Prompt Template

```
Ultra-detailed macro texture of [MINERAL DESCRIPTION], on a dark charcoal rock background, subtle geological structure, soft vignette and slightly brighter center to keep overlaid text readable, dark cinematic lighting, high-end editorial magazine texture, minimalist, no text, no logo
```

Replace `[MINERAL DESCRIPTION]` using the snippets listed below.

## Workflow & Integration

1. **Generation:** Use the prompts above with SDXL, Midjourney, or an editor of choice. Export to 16-bit TIFF/PNG when possible, then convert to WebP with ImageMagick or Squoosh CLI.
2. **Placement:** Store optimized assets inside `public/minerals/` using the slugs from the table.
3. **Mapping:** Update `lib/mineral-images.ts` so each slug points to `/minerals/<slug>.webp`, with a `default` entry for safe fallbacks.
4. **CMS metadata:** Continue using the `imageMineral` field in Contentlayer/MDX frontmatter so editors can explicitly pick the texture.
5. **Programmatic defaults:** When no explicit mineral is provided, choose one via `getRandomMineralImage()` or from a deterministic mapping derived from keywords (see docs/handbook for editorial routing). 
6. **Testing:** Preview textures on both light/dark themes to ensure overlays keep body copy accessible (WCAG AA). Consider adding an automated visual regression test once the pack ships.
